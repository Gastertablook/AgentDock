# ADR-001：单机版血缘失效广播用 Redis Pub/Sub 替代 Kafka

- 日期：2026-11-19
- 状态：已采纳

## 背景

lumina-framework 中，文档删除/更新后的缓存失效通过 Kafka 消息广播实现。AgentDock 当前为单人单机部署（docker-compose），引入 Kafka 需要额外维护 KRaft/Zookeeper，属于过度工程。

## 决策

单机版血缘失效广播改用 **Redis Pub/Sub**：
- 发布端：业务层删除/更新文档时 `PUBLISH` 一条携带 `parentId` 的消息；
- 订阅端：复用 lumina 的 `CacheInvalidationListener` 模式，收到消息后精确清理依赖该文档的 L1/L2 缓存。

同时抽象 `EventBroadcaster` 接口，屏蔽传输实现。

## 后果

**正面**：零新增基建；复用已移植的监听器模式；compose 单机即可运行完整一致性闭环。

**负面**：Redis Pub/Sub 不持久化——订阅端重启/断连期间的消息会丢失，存在缓存脏读风险窗口。个人单机场景可接受。

**演进路径**：多节点部署时替换为 Kafka（或 Redis Streams），仅需更换 `EventBroadcaster` 实现。被问"为什么不用 Kafka"时，此 ADR 即答案。
