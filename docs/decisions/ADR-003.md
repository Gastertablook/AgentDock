# ADR-003：沙箱网络策略分层——默认拒绝 + 按需受控出口（零信任 egress）

- 日期：2026-11-24
- 状态：已采纳

## 背景

原设计（M3 初稿）将沙箱统一设为 `--network none`（绝对断网）。但项目愿景（个人 AI 助理的信息采集管线）要求"开发并维护一个采集各大科技公司最新文章的爬虫 agent"——爬虫必须联网。断网与联网需求表面矛盾。

认知纠偏：**沙箱的本质不是"永远断网"，而是"默认拒绝 + 按需受控"（zero trust）**。断网只是默认档位；联网需求对应的是第二档位（受控出口），而非放弃沙箱。

## 决策

沙箱支持多 profile，网络策略分三层：

| 档位 | 网络形态 | 适用场景 |
|---|---|---|
| `isolated`（默认） | `--network none` 绝对断网 | 通用代码执行：写脚本、跑测试、数据处理 |
| `web-scrape` | 唯一网络路径是 egress-proxy | 爬虫/信息采集类任务（白名单域名） |
| 特权操作（演进蓝图） | 沙箱永不联网获权，走 MCP 代理模式 | 运维类操作（宿主侧 Daemon 校验后代为执行） |

**egress-proxy（受控出口代理）设计**——自研 Java 轻量实现（实现顺序：先用 Squid 配置验证链路，再替换为自研版）：
1. HTTP CONNECT 隧道 + **TLS SNI 解析**（ClientHello 提取目标域名，防 IP 直连绕过白名单）；
2. **域名白名单**（按任务类型配置，如科技媒体域名列表），白名单外 100% 拒绝；
3. **协议白名单**：仅放行 HTTP/HTTPS；
4. **每沙箱 token bucket 限流**（如 10 req/s）：防爬虫代码死循环高并发刷目标站（对应"高并发访问攻击场景"）；
5. **idle 连接超时**（如 30s 无数据断开）+ **每沙箱最大并发连接数**（如 8）+ 任务级总超时：防"长时间占用连接资源"；
6. **全量审计日志**：每个连接的域名、时长、字节数、拒绝原因——攻击取证 + 复盘素材 + 博客素材三合一；
7. 沙箱 DNS 解析也经由代理（防 DNS rebinding）；web-scrape 沙箱与 compose 内网隔离（防 SSRF 内网探测）。

沙箱容器本身在 web-scrape 档仍保留：`--cap-drop ALL`、内存/CPU/pids 限制、read-only 根文件系统。

## 后果

**正面**：
- 直接做实"网络出站拦截"的生产级答案（不止是断网演示）；
- 爬虫类 agent（贾维斯信息采集管线）有了可落地的执行底座；
- 攻击用例升级为恶意代码 + 网络攻防两组（QPS 限流/连接超时/SSRF 等均有验证报告）；
- 限流同时保护了目标网站（负责任的联网），是额外的工程叙事点。

**负面/残余风险**（写入风险 R5）：HTTP CONNECT 代理对非 HTTP 协议（如 DNS over HTTPS 之外的裸 TCP）仍有绕过面，单机演示版以"仅放行 HTTP(S) + SNI 校验 + 审计"兜底；生产级加固方向为 egress 网关 + 内核级策略（gVisor/Firecracker/eBPF，演进蓝图）。

**演进路径**：代理实现先 Squid（快）后自研 Java 版（深）；白名单/限流参数从任务 manifest 中声明（与 M7+ agent manifest 打通）。
